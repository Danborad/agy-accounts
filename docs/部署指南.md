# 部署指南（Debian 11/12）

本文从一台干净的 Debian 服务器开始，装好 [antigravity-server](https://github.com/AFSlayer/antigravity-server)，再叠加 `agy-accounts` 面板。

> 面板不下载、不修改 `agy-server`。两边升级互不阻塞，但升级后都要重跑验收。

---

## 0. 前置检查

```bash
cat /etc/os-release | head -2          # Debian 11/12
uname -m                               # x86_64
ldd --version | head -1                # glibc >= 2.28
python3 --version                      # >= 3.9
systemctl --version | head -1
```

需要 root 或 sudo。面板要控制 `agy-server` 的启停，默认以 root 运行。

---

## 1. 安装 agy-server

按上游文档操作：

```bash
curl -fsSL https://raw.githubusercontent.com/AFSlayer/antigravity-server/main/scripts/install.sh | bash
```

安装器会提示域名与工作目录，并创建 `agy-server.service`。

装完后确认：

```bash
systemctl status agy-server --no-pager
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8765/
```

然后打开网页，完成一次 Google 登录。确认令牌文件出现：

```bash
ls -l ~/.gemini/jetski-standalone-oauth-token
```

文件权限应为仅当前用户可读写。

> 如果你把 `agy-server` 装在其他用户下，注意面板里的 `HOME`、`token_path` 必须指向该用户的令牌。systemd 单元默认以 `root` 运行时，`HOME=/root`。

### 从桌面版复制令牌（可选）

```bash
scp ~/.gemini/jetski-standalone-oauth-token root@server:/root/.gemini/
systemctl restart agy-server
```

## 2. 安装 agy-accounts

```bash
git clone https://github.com/Danborad/agy-accounts.git
cd agy-accounts
sudo ./install.sh
```

交互输入至少 8 位的面板密码。脚本会：

- 安装到 `/opt/agy-accounts`
- 写配置 `/root/.config/agy-accounts/config.json`（权限 0600）
- 创建 `/root/.local/share/agy-accounts/accounts`（权限 0700）
- 创建 `/etc/systemd/system/agy-accounts.service`
- `systemctl enable --now agy-accounts`

常用参数：

```bash
sudo ./install.sh \
  --port 8790 \
  --agy-service agy-server \
  --token /root/.gemini/jetski-standalone-oauth-token \
  --app-url http://127.0.0.1:8765/
```

安装结束会跑一次自检，类似：

```
[ OK ] Python >= 3.9  3.11.2
[ OK ] 面板密码已配置  password_hash
[ OK ] 令牌目录存在  /root/.gemini
[ OK ] 线上令牌可读取  len=... sha256=...
[ OK ] 账号目录存在  /root/.local/share/agy-accounts/accounts
[ OK ] 面板静态文件存在  /opt/agy-accounts/web
[ OK ] 命令可用：stop  systemctl
[ OK ] 命令可用：start  systemctl
[ OK ] 命令可用：status  systemctl
[INFO] 服务状态：运行中
[INFO] 账号数量：0
```

令牌摘要只用于排错，日志与页面不会输出令牌内容。

## 3. 首次使用

1. 浏览器打开 `http://服务器地址:8790/`（本机可用 SSH 隧道，见第 5 节）
2. 输入面板密码
3. 确认顶部服务状态为「服务运行中」
4. 在 Antigravity 页面登录账号 A，回到面板，保存当前登录
5. 在 Antigravity 页面退出并登录账号 B，再保存
6. 在面板点「切换」测试来回切换

切换时面板会：

1. 校验目标快照
2. 若线上令牌已与目标相同，直接返回（不重启）
3. 若线上令牌与某个快照匹配，先写回该快照
4. 备份线上令牌
5. `systemctl stop agy-server`，并确认进程退出
6. 原子写入目标令牌
7. `systemctl start agy-server`
8. 轮询 `probe_url`，30 秒内返回 <500 即视为就绪
9. 成功则跳转 Antigravity；失败则回滚令牌并尝试重新启动

## 4. 以低权限用户运行（可选）

默认 root 最简单。若要与 `agy-server` 共用普通用户，或遵循最小权限：

```bash
sudo useradd --system --create-home --shell /usr/sbin/nologin agyaccounts
sudo ./install.sh --user agyaccounts
```

然后：

1. 给该用户令牌与快照目录权限：

```bash
sudo chown -R agyaccounts:agyaccounts /home/agyaccounts/.gemini /home/agyaccounts/.local/share/agy-accounts
```

2. 安装 sudoers：

```bash
sudo install -m 0440 deploy/agy-accounts.sudoers.example /etc/sudoers.d/agy-accounts
sudo visudo -c
```

3. 修改 `/home/agyaccounts/.config/agy-accounts/config.json`：

```json
{
  "stop_command":   ["sudo", "-n", "/usr/bin/systemctl", "stop", "agy-server"],
  "start_command":  ["sudo", "-n", "/usr/bin/systemctl", "start", "agy-server"],
  "status_command": ["sudo", "-n", "/usr/bin/systemctl", "is-active", "--quiet", "agy-server"]
}
```

4. 重启面板：

```bash
sudo systemctl restart agy-accounts
```

> 注意：如果 `agy-server` 本身以 root 运行，它的令牌在 `/root/.gemini`，普通用户默认读不到。更简单的做法仍是让面板以 root 运行，并只把面板监听限制在回环地址。

## 5. 远程访问

面板默认只监听 `127.0.0.1`。推荐顺序：

### 方案 A：SSH 隧道（最安全）

```bash
ssh -N -L 8790:127.0.0.1:8790 root@server
```

本机打开 `http://127.0.0.1:8790/`。

### 方案 B：Tailscale

```bash
tailscale up
```

把 `listen_host` 改为 Tailscale 地址或用 `tailscale serve` 暴露面板，确保只有自己的设备可达。

### 方案 C：反向代理 + HTTPS

在 Nginx/Caddy 上为面板单独开一个域名，加 Basic Auth 或仅允许内网网段。同时把配置改为：

```json
{
  "cookie_secure": true
}
```

并注意：

- 面板与 Antigravity 页面建议使用不同域名或路径，避免 Cookie 冲突
- 反向代理需传递 `Host` 与 `X-Forwarded-For`
- 不要把面板直接暴露到公网

---

## 6. 与 Antigravity 页面共存

面板不做请求转发，所以不存在路径冲突。若希望一个入口访问两者，可在反向代理层做：

- `accounts.example.com` → 面板 `127.0.0.1:8790`
- `agy.example.com` → `agy-server` `127.0.0.1:8765`

把配置里的 `app_url` 改成 `https://agy.example.com/`，切换成功后就会跳转到正确地址。

## 7. 升级

```bash
cd agy-accounts
git pull
sudo ./install.sh
```

`install.sh` 会保留已有配置与账号快照，只替换程序文件并重启服务。

升级后：

```bash
python3 /opt/agy-accounts/agy_accounts.py --config /root/.config/agy-accounts/config.json check
```

再按验收清单抽测切换与回滚。

---

## 8. 卸载

```bash
sudo ./uninstall.sh           # 保留配置与账号快照
sudo ./uninstall.sh --purge   # 连同配置、快照、secret.key 一起删除
```

令牌文件本身不会被删除。`agy-server` 不受影响。

---

## 9. 备份

要备份的只有两处：

```bash
/root/.config/agy-accounts/          # 配置 + secret.key
/root/.local/share/agy-accounts/     # 账号快照（凭据）
```

这两处等同密码库：

- 不要提交到 Git
- 不要放进公开网盘
- 迁移机器时用 `scp`/`rsync` 并保持 0600 / 0700 权限

`secret.key` 丢失只会让现有面板会话失效，不影响账号快照；重新登录即可。

---

## 10. 日志与排错

```bash
systemctl status agy-accounts --no-pager
journalctl -u agy-accounts -n 100 --no-pager
journalctl -u agy-server -n 100 --no-pager
```

面板日志会记录：

- 启停命令与退出码
- 登录失败 IP
- 切换开始/结束
- 令牌长度与 SHA-256 前 8 位（不记录内容）

不会记录密码、Cookie 或令牌正文。
